# T-06 語意分割模型測試報告

- **模型**：`nvidia/segformer-b4-finetuned-ade-512-512`（ADE20K，150 類）
- **裝置**：Apple Silicon MPS，PyTorch 2.8.0 / transformers 4.57.6
- **腳本**：`scripts/test_segmentation.py`
- **產出**：`output/seg/<名稱>_seg.png`（原圖｜疊色圖 並排 ＋ 圖例）、
  `output/seg/<名稱>_labelmap.npy`（原尺寸 uint8 label map）、`output/seg/stats.json`（完整佔比統計）
- **輸入**：`assets/photos/` 共 9 張，全部處理成功
- **推論方式**：processor 縮到 512×512 → logits (150, H/4, W/4) → bilinear 上採樣回原圖尺寸 → argmax

> 本報告的每個數字都來自實際執行 `scripts/test_segmentation.py` 與對 `_labelmap.npy` 的區域統計，
> 沒有任何估計值或杜撰值。

## 0. T-04 五類空間覆蓋對照表

T-04 要求的五類：浴室／客廳／教堂或大空間／樓梯間走廊／車內。

| T-04 類別 | 對應照片 | 覆蓋 |
|---|---|---|
| 浴室 | `bathroom_tiled` | ✅ |
| 客廳（一般起居空間） | `bedroom_ai_generated`（臥室） | ⚠️ 以臥室代替客廳。聲學上同屬「軟裝為主的小型居室」，但沙發/大面積軟墊家具未被涵蓋 |
| 教堂／大空間 | `arena_ntsu_linkou`（體育館）、`livehouse_riverside_ximen`（Live House）、`cgi_cave_lab_sophy`、`cgi_cavern_crowd_sophy` | ✅ 4 張，但**沒有一張是真實的教堂/長殘響硬質大空間**——體育館與 Live House 都是滿場人群（高吸音），CGI 兩張不是真實空間 |
| 樓梯間／走廊 | `stairwell_tiled`、`corridor_hotel_carpet` | ✅ 且互補（一硬一軟） |
| 車內 | `car_interior_suv` | ✅ |

**缺口**：缺「真實、空場、硬質表面的大空間」（教堂、體育館空場、停車場）。
目前所有大空間樣本都被人群主導，無法驗證長殘響情境的分割品質。

## 1. 一句話結論

**牆/地板/天花板在「一般建築室內」被正確分出（bedroom、bathroom、corridor、stairwell 四張品質可用），
但在「非建築空間」（車內、CGI 洞窟）與「人群主導的大空間」（體育館、Live House）會系統性失敗，
且模型對失敗毫無自覺——它一律輸出高置信度的 wall/floor/ceiling。**

對本專案而言，最致命的不是「分不出來」，而是**分錯了但看起來很合理**：
最嚴重的兩例是 `corridor_hotel_carpet` 的滿鋪地毯被 70% 判成 `floor`（→ 會 fallback 成硬質地面，
4kHz 吸音係數差 32 倍），以及 `car_interior_suv` 的整個車室被判成 `wall`。

## 2. 逐張觀察

### 2.1 `bedroom_ai_generated`（臥室，AI 生成影像）— **本批最佳**

| 類別 | 佔比 |
|---|---|
| wall | 34.55% |
| bed | 21.15% |
| floor | 16.32% |
| curtain | 8.95% |
| windowpane | 5.66% |
| painting | 4.63% |
| person | 3.23% |
| desk / swivel chair | 2.41% / 2.06% |

- **牆/地板：✅ 完全正確。** 背牆、木地板邊界乾淨，透視收斂處沒有滲色。
- **窗簾：✅ 正確分出 `curtain` 8.95%**，左側與中央兩片窗簾都抓到，且沒有與 `wall` 混淆。
  這對 RT60 很重要（curtain_fabric 1kHz α=0.72 vs generic_wall 0.03）。
- **天花板：❌ 完全沒有 `ceiling` 類別（0 px）。** 但這是取景問題不是模型問題——原圖根本沒拍到天花板。
  **這暴露一個管線層級的問題：單張照片常常拍不到天花板，而天花板是室內最大的單一表面之一。**
  Sabine 公式需要總表面積，缺天花板會系統性低估吸音面積 → RT60 高估。
- **牆上海報被分成 `painting` 4.63%**：語意正確，聲學上是貼牆紙張，可併入 wall 處理。
- **AI 生成影像可信度：✅ 高。** 這張圖幾何一致、材質貼圖正常，分割結果與真實臥室照片無異。
  結論是「AI 生成」本身不必然造成分割失敗，**造成失敗的是不合物理的幾何**（見 CGI 兩張）。

### 2.2 `bathroom_tiled`（磁磚浴室）— 鏡子與玻璃門是關鍵

| 類別 | 佔比 |
|---|---|
| screen door | 30.54% |
| wall | 29.07% |
| cabinet | 14.07% |
| **mirror** | **10.36%** |
| floor | 6.79% |
| toilet | 5.38% |
| sink / ceiling / countertop | 2.34% / 0.86% / 0.59% |

**鏡子（任務重點 #2）——實際檢查結果：**

- **鏡子被正確辨識為 `mirror`（10.36%），沒有被誤判成 window 或 wall。** 這點是好消息。
- 對鏡子 bbox（x 11–288, y 0–424）內做像素統計：`mirror 82.0% / wall 16.9% / cabinet 1.1%`。
  - 16.9% 的 `wall` 是 bbox 為矩形而鏡子有透視傾斜造成的，不是誤判。
  - **1.1% 的 `cabinet` 才是真正的反射洩漏**：鏡面右下角「反射出來的洗手檯櫃體」被獨立標成了
    真實的 `cabinet`（見疊圖右上鏡面內的黃綠色斑塊）。
  - 換算成全圖只有 **0.14%**，量很小。
- **結論：反射洩漏存在但輕微；真正的問題是別的**——`mirror` 佔了 10.36% 的畫面，
  而 `data/materials.json` **沒有 mirror 這一項**。若 fallback 到 `generic_wall`
  （4kHz α=0.05），會低估這面硬玻璃的反射性（glass 4kHz α=0.04 才對，
  但 generic_wall 低頻 α=0.013 vs glass 0.35，低頻差 27 倍）。

**玻璃淋浴門（更嚴重的問題）：**

- 整個淋浴間被判成 **`screen door` 30.54%**，而且**不只是玻璃門本身**——
  疊圖顯示這塊桃紅色區域把**玻璃門後面的磁磚牆與淋浴底盤一起吞進去了**。
- 也就是說：浴室裡最硬、最不吸音的兩面磁磚牆（marble，全頻段 α≈0.01–0.02）
  在表面積統計中會被當成「門」。這是**表面積歸類錯誤，不是細節誤差**，
  對浴室這種靠硬表面產生長殘響的空間影響極大。

**磁磚牆 vs 磁磚地：**
- 牆 `wall` 29.07%、地 `floor` 6.79%，兩者確實分開了。
- 但 **ADE20K 沒有「磁磚」這個材質類別**——牆的磁磚與油漆牆同樣叫 `wall`，
  地的磁磚與木地板同樣叫 `floor`。**分割模型只給幾何角色，不給材質。**

### 2.3 `corridor_hotel_carpet`（飯店走廊）— **本批最危險的失敗**

| 類別 | 佔比 |
|---|---|
| wall | 53.58% |
| **floor** | **14.53%** |
| door | 12.30% |
| ceiling | 7.16% |
| cabinet | 6.27% |
| **rug** | **6.11%** |

**地毯 vs 地板（任務重點 #3）——實際檢查結果：**

- 原圖的地面是**一整塊滿鋪（wall-to-wall）紅色花紋地毯**，中央有一條花紋較密的走道紋樣。
- 模型把這**同一塊地毯切成兩類**：
  - `rug` 6.11% ＝ 只有中央花紋較密的那條帶狀紋樣
  - `floor` 14.53% ＝ 兩側的素色地毯
- 換算：**地面總面積中只有 29.6% 被判成 `rug`，70.4% 被判成 `floor`。**
- **模型是依「花紋圖案」而不是「材質」在切分的。**
- **聲學後果（這是本任務最重要的單一發現）**：
  若 `floor` → 硬質地面（marble 4kHz α=0.02）、`rug` → carpet（4kHz α=0.65），
  則這片地毯的等效吸音只會算到 `0.296×0.65 + 0.704×0.02 = 0.207`，
  而正確值應是 0.65 —— **高頻吸音被低估到只剩 32%，RT60 會被大幅高估**。
- **`floor` 這個類別在本專案裡是不可信的**，它只代表「這是地面」，不代表任何材質。

**其他：**
- 左右兩側深色木質門框/門套被判成 `cabinet` 6.27%（bbox x 31–1246, y 201–1167，橫跨畫面兩側）。
  語意錯誤，但聲學上 cabinet 與 door 都會對到木材，影響不大。
- `door` 12.30% 抓到走廊兩側的門片，深度方向遠處的門也有抓到，這部分表現不錯。
- `ceiling` 7.16% 正確。這是本批**唯一一張牆/地/天花板三者都被正確分出的真實照片**。

### 2.4 `stairwell_tiled`（磁磚樓梯間）

| 類別 | 佔比 |
|---|---|
| wall | 45.02% |
| stairway | 19.32% |
| ceiling | 12.72% |
| railing | 7.72% |
| bannister | 6.35% |
| windowpane | 5.70% |
| floor | 3.16% |

- **`stairway` 19.32% 有被正確分出**，階梯踏面/踢面整片抓到，邊界貼合度不錯。
- **`ceiling` 12.72% 實際上是「上層樓梯的斜向底板」**（疊圖左上的土黃色區域）。
  語意上叫 ceiling 有點勉強，但**聲學上是對的**——那確實是一個朝下的頂面反射面，
  對這種樓梯間的 flutter echo 有直接貢獻。這算是一個「幸運的正確」。
- `railing` 7.72%（垂直欄杆柱）與 `bannister` 6.35%（斜向扶手）被拆成兩類。
  兩者是同一組鐵件，**對聲學是「非表面物件」，應在管線中一起排除或當散射體處理，不要計入表面積**。
- **全圖 45.02% 的 `wall` 底下 100% 是釉面磁磚牆，但模型只給了 `wall`。**
  再次確認：磁磚牆與抹灰牆在 ADE20K 中無法區分。
- `floor` 3.16% 是底部的樓梯平台，正確。

### 2.5 `livehouse_riverside_ximen`（河岸留言 Live House）

| 類別 | 佔比 |
|---|---|
| wall | 41.02% |
| person | 36.01% |
| curtain | 14.67% |
| floor | 3.77% |
| ceiling | 2.60% |
| stage | 1.88% |

- **`curtain` 14.67% 有抓到舞台後方的深色布幕**——這是好消息，
  Live House 的深色布幕是主要吸音體（curtain_fabric 1kHz α=0.72）。
- `person` 36.01%：前景人頭與台上樂手都算進去，數量正確但**前景人頭嚴重遮擋了地板與側牆**，
  `floor` 只剩 3.77%。**遮擋導致的表面積不可觀測，是照片式管線的固有限制**，模型無法補救。
- `wall` 41.02% 偏高：疊圖顯示 wall 把舞台上方的暗部、側面的音響器材區都吞了。
  暗部區域模型基本上是在「猜」。
- `stage` 只有 1.88%，實際舞台面積明顯大於此，其餘被 person 蓋掉。

### 2.6 `arena_ntsu_linkou`（林口體育館演唱會）

| 類別 | 佔比 |
|---|---|
| **ceiling** | **44.50%** |
| grandstand | 30.56% |
| wall | 13.94% |
| person | 9.36% |
| stage / screen / lamp / signboard | 0.72% / 0.62% / 0.15% / 0.12% |

- **`grandstand` 30.56% 是本批最貼切的類別對應**：ADE20K 有專門的看台類，
  正好對應 `materials.json` 的 `audience_seating`。這是唯一一個「類別語意 = 聲學材質」的漂亮對應。
- **但 `ceiling` 44.50% 高度可疑**：實測顯示畫面最上方 5.5% 的區域是 **100% `ceiling`**，
  而其中 rows 0–47（全圖 2.67%）是 **YouTube 標題列的純黑底**（整列平均亮度 < 25）。
  也就是說 **44.50% 的 ceiling 裡有 2.67 個百分點是 YouTube UI 黑底冒充的**。
- **全圖 `floor` = 0 px。** 體育館的內場站區完全沒有被判成地板，而是被 grandstand / wall / person 瓜分。
  抽查畫面中央的舞台區（x 30–55%, y 55–75%）得到 `wall 35.5% / grandstand 27.1% / stage 12.5% / screen 12.3%`
  ——**模型在強舞台燈光與煙霧下把地面判成了「牆」**。
- 舞台燈光光束（畫面中大量白色射線）造成類別邊界破碎，疊圖上可看到 grandstand 與 person
  在光束處交錯切換。**強光/煙霧是明確的失敗誘因。**

### 2.7 `cgi_cave_lab_sophy`（CGI 洞窟實驗室）— 非真實空間

| 類別 | 佔比 |
|---|---|
| wall | 69.81% |
| floor | 26.56% |
| table | 2.49% |
| ceiling | 1.07% |
| glass | 0.08% |

- 模型**極度自信地**把整個奇幻洞窟（鐘乳石狀有機結構、拱形洞頂）全部歸成一片 `wall` 69.81%。
- **`ceiling` 只有 1.07%**：真正的洞頂拱面全被算進 `wall`，天花板實質上沒有被分出來。
- 中央的岩石平台被判成 `table` 2.49%——物件幻覺，但無傷大雅。
- **黑邊污染在這張最嚴重**：頂部 rows 0–59（全圖 3.33%）純黑 → **100% `wall`**；
  底部 rows 1710–1799（全圖 5.00%）純黑 → **100% `floor`**。
  **報告的 26.56% `floor` 裡有 5.00 個百分點（＝ 該類別的 18.8%）是純黑 UI 黑邊，不是地板。**
- **可信度判定：❌ 不可用。** 分割「語意」上勉強說得通（那確實是圍蔽面），
  但材質完全錯——濕岩壁會被對到 `generic_wall`（抹灰，4kHz α=0.05），
  實際應接近 `concrete`/`brick`。且模型不會告訴你它在猜。

### 2.8 `cgi_cavern_crowd_sophy`（CGI 巨型洞窟）— 非真實空間

| 類別 | 佔比 |
|---|---|
| person | 52.97% |
| wall | 20.43% |
| earth | 13.80% |
| ceiling | 9.57% |
| water | 2.03% |
| painting | 0.94% |
| sky | 0.25% |

- `person` 52.97%：人群本身抓得很好，這部分可信。
- **明確的幻覺證據**：在一個封閉洞窟裡同時出現 `sky` 0.25%、`painting` 0.94%、`water` 2.03%。
  疊圖顯示右上方一個發亮的洞口被判成 `water`（藍色區塊），左上的巨大隧道口被判成 `ceiling`（橘色）。
  **`sky` 出現在室內場景，是「模型正在猜」的可直接偵測訊號——建議做成管線的自動警示條件。**
- 地面被拆成 `earth` 13.80% 與部分 `wall`——`wall` 被塗到人群之間的濕地面上（疊圖中人腳邊的紅色）。
  **地面與牆面的區分在此完全失效。**
- 黑邊污染：底部 rows 1765–1799（全圖 1.94%）純黑 → `earth 85.8% / person 14.2%`。
- **可信度判定：❌ 不可用。**

### 2.9 `car_interior_suv`（SUV 車內後座）— **預期中的最大失敗案例，已證實**

| 類別 | 佔比 |
|---|---|
| seat | 45.58% |
| **wall** | **33.03%** |
| door | 10.03% |
| windowpane | 8.44% |
| floor | 2.72% |
| ceiling | 0.19% |

**實際檢查結果（任務重點 #1）：**

- **`seat` 45.58% 是唯一正確的部分**——前後座椅都抓到了。ADE20K 的 `seat` 是為劇院座椅設計的，
  剛好套用在車座上。
- **`wall` 33.03% 是一個垃圾桶類別**。逐區抽查 `_labelmap.npy` 證實它同時包含了：

  | 抽查區域（相對座標） | 結果 |
  |---|---|
  | 車頂內襯 (x 45–70%, y 2–7%) | `wall 71.7%, windowpane 28.3%` |
  | 右後窗**窗外樹林** (x 38–46%, y 12–28%) | **`wall 92.4%`** |
  | 左後窗**窗外樹林** (x 10–20%, y 10–30%) | `wall 52.6%, windowpane 47.3%` |
  | 畫面最右**車體外殼（橘色烤漆，在車外）** (x 96.5–100%, y 20–80%) | **`wall 100.0%`** |

- **兩個獨立的致命錯誤：**
  1. **車頂內襯（headliner）被判成 `wall` 而不是 `ceiling`——全圖 `ceiling` 只有 0.19%。**
     車內最大的吸音面（絨布頂棚）在管線中會消失。
  2. **玻璃窗外的樹林被判成 `wall`（92.4%）。** 模型把「隔著玻璃看到的室外景物」
     當成了實體牆面。若拿去算表面積，會憑空生出一大片不存在的反射牆。
     `windowpane` 8.44% 只抓到部分窗格，大部分窗戶都漏了。
- `floor` 2.72% 只有腳踏區一小塊；`door` 10.03% 只抓到左後門內飾板。

**這張圖給 Phase 1 的結論（必須寫進限制清單）：**
ADE20K 是**建築室內／戶外場景**資料集，沒有任何車輛內裝類別
（沒有 headliner、dashboard、車窗玻璃、儀表板、A/B/C 柱）。
**目前的材質辨識管線對「非建築空間」（車內、機艙、電梯、櫥櫃內部）是無能為力的，
而且會安靜地輸出看似合理的錯誤結果。** 若 SPEC 要支援車內殘響，
必須換模型或加一個「這是不是建築空間」的前置分類器把它擋掉。

## 3. YouTube 黑邊／字幕／播放器 UI 的污染（任務重點 #5）

前 5 張是 YouTube 播放器截圖。**模型完全不知道 UI 的存在，它把 UI 併進了鄰近的場景類別。**

**A. 純黑 letterbox 黑邊**（判定方式：整列 RGB 平均亮度 < 25）

| 照片 | 黑邊位置 | 佔全圖 | 被分成 |
|---|---|---|---|
| `arena_ntsu_linkou` | rows 0–47（頂部標題列） | 2.67% | **`ceiling` 100.0%** |

### 4.2 對應不到的缺口清單（給 T-07 / Phase 1）

**缺口 A：ADE20K 有類別，但 `materials.json` 沒有對應材質**
1. `mirror`（本次 10.36%）— 需要新增，α 可沿用 `glass`
2. `screen door`（本次 30.54%）— 玻璃／紗門，需要新增或明確併入 `glass`
3. `bed` / `pillow` / `swivel chair`（本次合計 23.71%）— **軟墊家具完全沒有材質項。**
   一般居室最主要的吸音體就是床、沙發、軟墊椅，這是 `materials.json` 目前最大的缺口
4. 未在本批出現但一定會遇到：`sofa`(23)、`armchair`(30)、`cushion`(39)、`plant`(17)、`book`(67)

**缺口 B：`materials.json` 有材質，但 ADE20K 沒有任何類別可以觸發它**

| 材質 id | 現況 |
|---|---|
| `marble` | 只能從 toilet/sink 間接觸發。**磁磚牆／大理石地板沒有專屬類別**（都是 wall / floor） |
| `carpet` | 只能靠 `rug`，而 `rug` 對滿鋪地毯召回率只有 29.6% |
| `brick` | ADE20K 無 brick 類別，清水磚牆一律是 `wall` |
| `concrete` | 同上，無專屬類別 |
| `acoustic_panel` | **完全無法觸發。** ADE20K 沒有吸音板類別，錄音室/會議室的吸音板會被判成 `wall` |
| `wood_panel` | 只能靠 door/cabinet/table 間接推。木飾板牆面一律是 `wall` |

**缺口 C：結構性問題（換材質表也解決不了）**
1. **語意分割只給「幾何角色」，不給「材質」。** `wall` / `floor` 這兩個佔比最大的類別
   （本批 9 張合計佔比總和 340% + 74%）幾乎不帶材質資訊。
   **T-07 之後若直接用 wall→generic_wall、floor→某個預設值，等於整個材質辨識功能是假的。**
   → 建議 Phase 1 必須在分割之後再接一層**材質分類器**（對每個 wall/floor 區塊裁圖再分類），
      或改用 CLIP zero-shot 對區塊問「這是磁磚/木頭/地毯/混凝土嗎」。
2. **無「非建築空間」偵測**。車內、CGI 洞窟都會安靜地產生看似合理的錯誤。
   → 建議加一個防呆規則：`ceiling < 1%` 或（室內場景卻出現 `sky`）或 `seat > 40%` 時發出警告。
3. **模型不輸出置信度。** 目前腳本只做 argmax。若 Phase 1 要做防呆，
   應改為輸出 softmax 最大值當作 per-pixel 置信度並記錄平均值。

## 5. 已知限制與本任務未做的事

- 只做單張推論，**沒有做多尺度/翻轉 TTA**，邊界品質可再提升。
- **沒有人工標註 ground truth**，所有「正確/錯誤」判定都是對疊圖的目視判斷 ＋ 對 label map 的區域統計，
  屬於定性評估，沒有 mIoU 這類量化指標。
- 沒有比較 b0/b2/b5 等其他尺寸，無法判斷失敗是模型容量問題還是資料集覆蓋問題
  （但車內／CGI 的失敗明顯是**資料集覆蓋**問題，換大模型救不了）。
- 未實作任何 UI 裁切或後處理，報告中的所有佔比都是**未修正的原始輸出**。
